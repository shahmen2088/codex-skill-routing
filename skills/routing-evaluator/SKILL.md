# Routing Evaluator

Создать независимый набор запросов до изменения routing metadata или использовать заранее сохранённый набор.

Для каждого skill включить:

- прямой запрос с явной целью;
- косвенную формулировку той же цели;
- follow-up, который зависит от предыдущего результата;
- отрицательный запрос, где skill не должен активироваться;
- boundary case около заявленной границы;
- collision case с ближайшим похожим skill.

Для каждого случая зафиксировать ожидаемые primary/supporting skills, допустимый `no-match`, topology и запрещённые активации. Запустить случаи в новых сессиях после изменения metadata.

Отчёт должен содержать:

- route accuracy для однозначных случаев;
- false activations и missed activations;
- unnecessary supporting skills;
- нестабильность между близкими формулировками;
- минимальные изменения `name`, `description` или границ, подтверждённые ошибками.

Не улучшать результат под один пример ценой более широкой ложной активации. После правки повторить весь затронутый набор, включая negative cases.
