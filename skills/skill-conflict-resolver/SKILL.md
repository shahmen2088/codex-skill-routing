# Skill Conflict Resolver

1. Выписать только конфликтующие утверждения, их источники и затронутый результат.
2. Применить приоритет: явный запрос пользователя → системные ограничения и безопасность → проектные инструкции → специализированный skill → общий skill.
3. Не трактовать skill как новое разрешение на отправку, публикацию, удаление, оплату или изменение внешнего состояния.
4. Удалить дублированные шаги и назначить одного владельца каждого side effect.
5. Если инструкции совместимы, объединить их в минимальный порядок. Если несовместимы и выбор существенно меняет результат, показать конфликт и запросить одно решение пользователя.
6. Сохранить требования проверки каждого выбранного skill; конфликт процесса не отменяет критерии качества.

Вернуть: применённый приоритет, сохранённые ограничения, исключённые инструкции, окончательный порядок и нерешённый вопрос либо `none`.
