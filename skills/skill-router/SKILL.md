# Skill Router

Выдать маршрут по контракту из [`../../references/routing-contract.md`](../../references/routing-contract.md), не выполняя предметную задачу.

1. Сохранить явно выбранный пользователем skill. Не добавлять другие навыки, если они не нужны для результата.
2. Выделить цель, входы, ожидаемый артефакт, действия, ограничения, риск и требуемую проверку.
3. Сравнить запрос только с именами и описаниями доступных skills. Не читать весь каталог.
4. Исключить кандидатов, чьи границы или отрицательные условия совпадают с запросом.
5. Оценить оставшихся по четырём сигналам: цель пользователя, тип входа/выхода, предметная область и необходимые инструменты.
6. После shortlist прочитать тела только сильнейших кандидатов, чтобы проверить prerequisites, side effects и пересечения.
7. Выбрать один основной skill и до двух вспомогательных. Если несколько независимых областей действительно нужны, передать набор в `workflow-router`.
8. Указать `high`, `medium` или `low` confidence с причиной. При низкой уверенности задать один вопрос только тогда, когда разные ответы меняют маршрут; иначе вернуть `primary: null`.

Не выдумывать навык по ключевому слову, не выбирать несколько почти одинаковых skills «на всякий случай» и не считать каталог обязательным для каждой задачи.
