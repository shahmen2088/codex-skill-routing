# Workflow Router

Перед проектированием нескольких исполнителей проверить, может ли один агент с одним skill надёжно завершить задачу. Дополнительный hop оправдан только изоляцией контекста, настоящим параллелизмом, несовместимыми ролями или независимой проверкой.

1. Разбить цель на результаты с наблюдаемыми критериями готовности.
2. Построить зависимости: какой результат нужен следующему шагу и какие операции меняют общее состояние.
3. Выбрать topology по [`../../references/topologies.md`](../../references/topologies.md).
4. Параллелить только независимые чтения или изолированные артефакты. Записи, публикации, отправки и изменения общего состояния сериализовать.
5. Для каждого handoff передать цель, входы, разрешения, ограничения, формат выхода, критерий готовности и лимит повторов. Не передавать полную историю, если достаточно ссылок и краткого контекста.
6. Назначить точку синтеза и проверку итогового результата. Ограничить глубину делегирования и число повторов.

Вернуть topology, граф порядка, назначенные skills, handoff contracts и verification plan. Не запускать исполнителей, если запрос ограничен проектированием маршрута.
